### Observations from actual usage:

1. **`run` is only used for plain training** (2 configs, no sweeps). Could be `simulate --mode=training`.
2. **`simulate` is the workhorse** — handles training sweeps, online learning sweeps, and is the only command used for the paper experiments.
3. **`evaluate` is used for pre-trained model evaluation** with optional sweeps (SNR, eta, kalman_noise).
4. **`online_learning` is used for standalone OL and 4D grid** — but the main eta sweep experiments actually use `simulate --mode=online_learning`, not this command.
5. **The eta sweep paper experiments do NOT use `online_learning` command** — they use `simulate`. The `online_learning` command is only used for the 4D grid and single-run debugging.

## Overview

All commands share a common entry pattern:

```
CLI args → setup_configuration(config, output, override) → Simulation(config, components, output_dir) → <command-specific logic>
```

---

## 1. `run` Command

### Core Function Flow

```
run_command()
  → setup_configuration()
  → Simulation(config, components, output_dir)
  → sim.run_training()       [scenario='training']
  → sim.run_evaluation()     [scenario='evaluation']
  → sim.execute_online_learning()  [scenario='online_learning']
  → sim.run()                [scenario='full' → chains training → evaluation → online_learning]
```

### Main Configurables

| Option | Type | Description |
|--------|------|-------------|
| `--scenario` | Choice: `training`, `evaluation`, `online_learning`, `full` | Which pipeline to execute |
| `-c` | str | Config YAML path |
| `-o` | str | Output directory override |
| `--override` | str (multiple) | Dot-path config overrides |

### Driving YAML

Any config YAML — no scenario sweep logic. Just runs a single pass of the chosen pipeline.

Example: `configs/default_config.yaml`

### Result Structure

Depends on scenario chosen:
- **training**: `{"status": "success", "trained_model": True/False}`
- **evaluation**: `{"status": "success", "evaluation_results": {...}}`
- **online_learning**: `{"status": "success", "online_learning_results": {...}, "drift_detection_dicts": [...]}`
- **full**: Merged dict of all three above

### Plots

None generated by this command directly.

## 2. `evaluate` Command

### Core Function Flow

```
evaluate_command()
  → setup_configuration() [with train_model=false, load_model=true, evaluate_model=true]
  → Simulation(config, components, output_dir)
  │
  ├─ [no scenario] → sim.run_evaluation()
  │
  ├─ [scenario='kalman_noise'] → 2D nested loop:
  │     for meas_noise × proc_noise:
  │       sim._run_sweep_iteration(overrides, ..., full_mode=False)
  │         → apply_overrides() → update_components_for_sweep() → Simulation() → .run_evaluation()
  │
  └─ [scenario=snr/eta/m/...] → sim.run_scenario(scenario, values, full_mode=False)
        → core.py: for value in values: _run_sweep_iteration() → .run_evaluation()
```

### Main Configurables

| Option | Type | Description |
|--------|------|-------------|
| `--model` / `-m` | str (required) | Path to pre-trained `.pt` model |
| `--scenario` / `-s` | str | Parameter to sweep: `snr`, `eta`, `m`, `kalman_noise` |
| `--values` / `-v` | float (multiple) | Sweep values (CLI or config or defaults) |
| `--trajectory` | flag | Enable trajectory-based data |

Fallback defaults (when no values from CLI or config):
```python
{"eta": [0.0, 0.01, 0.05, 0.1, 0.2, 0.3, 0.5],
 "snr": [-10, -5, 0, 5, 10, 15, 20],
 "m":   [1, 2, 3, 4, 5]}
```

### Driving YAMLs

- `configs/evaluation_configs/snr_sweep_config.yaml` (SNR sweep)
- `configs/evaluation_configs/calibration_sweep_error_config.yaml` (eta sweep)
- `configs/evaluation_configs/source_count_config.yaml` (M sweep)

### Result Structure

- **Single eval** (no scenario): `{"status": "success", "evaluation_results": {<metric_name>: value, ...}}`
- **Scenario sweep**: `{value_1: {result_dict}, value_2: {result_dict}, ...}`
- **Kalman noise 2D**: `{meas_noise_1: {proc_noise_1: {result}, proc_noise_2: {result}}, ...}`

### Plots

| Scenario | Plot Function | Output |
|----------|--------------|--------|
| `kalman_noise` | `plot_2d_kalman_noise_sweep(scenario_results, output_dir)` | Heatmap of loss across noise combos |
| Any other | `plot_loss_vs_scenario(scenario_results, scenario, output_dir)` | Line plot: loss vs swept parameter |

## 3. `simulate` Command

### Core Function Flow

```
simulate_command()
  → setup_configuration()
  → Simulation(config, components, output_dir)
  │
  ├─ [scenario + values provided]:
  │     sim.run_scenario(scenario, values, full_mode=(mode=='full'))
  │       → core.py: for value in values:
  │           ├─ [eta + lr_sweep enabled]:
  │           │     for lr in static_lr_list: _run_sweep_iteration()
  │           │     [adaptive]: _run_sweep_iteration()
  │           │     → _aggregate_and_save_heatmap_data()
  │           └─ [standard]:
  │                 _run_sweep_iteration(overrides, ..., full_mode)
  │                   → apply_overrides → update_components → Simulation
  │                   → .run_training() / .run_evaluation() / .execute_online_learning() / .run()
  │
  └─ [no scenario]:
        → sim.run()                    [mode='full']
        → sim.execute_online_learning() [mode='online_learning']
        → sim.run_training()            [mode='training']
```

### Main Configurables

| Option | Type | Description |
|--------|------|-------------|
| `--scenario` / `-s` | str | Parameter to sweep (SNR, T, M, eta, etc.) |
| `--values` / `-v` | float (multiple) | Sweep values |
| `--mode` | Choice: `training`, `full`, `online_learning` | Pipeline mode |
| `--trajectory` | flag | Enable trajectory-based data |
| (from config) `scenario_config.type` | str | Fallback scenario type |
| (from config) `scenario_config.values` | list | Fallback sweep values |
| (from config) `scenario_config.model_paths` | list | Per-sweep-value model paths |
| (from config) `online_learning.enable_lr_sweep` | bool | Enables LR sweep within eta scenario |
| (from config) `online_learning.static_lr_list` | list | LR values to sweep |
| (from config) `online_learning.use_adaptive_learning_rate` | bool | Include adaptive LR run |

### Driving YAMLs

- `configs/Used_for_paper/SineAccel_base_model_Online_learning_eta_sweep_config.yaml` (eta sweep + online learning)
- `configs/Used_for_paper/SineAccel_base_model_Online_learning_snr_sweep_config.yaml` (SNR sweep)
- `configs/Used_for_paper/Random_base_model_training_snr_scenario_config.yaml` (training SNR scenario)
- `configs/Used_for_paper/Random_basemodel_training_config.yaml` (plain training)

### Result Structure

- **No scenario (single run)**: Same as `run` command result for chosen mode
- **Scenario sweep**: `{value_1: result_dict, value_2: result_dict, ...}`
- **Eta with LR sweep**: 
  ```
  {eta_value: {
      "lr_sweep_results": {
          0: {"lr_type": "static", "lr_value": 0.001, "result": {...}, "avg_rmspe_loss": float},
          1: {"lr_type": "static", "lr_value": 0.01, ...},
          "adaptive": {"lr_type": "adaptive", "lr_value": float, ...}
      },
      "standard_result": None
  }}
  ```
- **Saved to disk**: `drift_detection_dicts.json`, `lr_sweep_heatmap_data.json`

### Plots

| Condition | Plot Function | Output |
|-----------|--------------|--------|
| `scenario='snr'` + `mode='online_learning'` | `plot_scenario_results(results, output_dir)` | Averaged loss comparison across SNR |
| | `plot_performance_improvement_table(results, output_dir)` | Table of improvement metrics |
| `scenario='eta'` + `mode='online_learning'` | `plot_eta_scenario_comparison(results, output_dir)` | Drift detection comparison (window, z-score, LR) |
| | `plot_performance_improvement_table_eta(results, output_dir)` | Table of eta improvement metrics |
| | `plot_scenario_results(results, output_dir, scenario_type='eta')` | Averaged comparison per eta |
| | `plot_lr_sweep_heatmap(heatmap_data, output_dir)` | Heatmap: eta × LR → loss (if lr_sweep enabled) |

## 4. `online_learning` Command

### Core Function Flow

```
online_learning_command()
  → setup_configuration()
  → apply_overrides([train_model=false, load_model=true, online_learning.enabled=true])
  │
  ├─ [scenario='4d_grid']:
  │     for proc_noise × kf_proc_noise × kf_meas_noise × eta:
  │       Simulation(modified_config, components, output_dir)
  │         ._run_sweep_iteration(grid_overrides, ..., full_mode=False)
  │           → apply_overrides → update_components → Simulation → .execute_online_learning()
  │
  └─ [no scenario]:
        Simulation(modified_config, components, output_dir)
          .execute_online_learning()
            → OnlineLearning(config, system_model, trained_model, output_dir, results)
              .run_online_learning()
                → _run_single_trajectory_online_learning() [per trajectory in dataset_size]
                  → trajectory_generator.get_next_window()
                  → _evaluate_window()
                  → _online_training_window() [with GLRT + adaptive LR]
                  → _evaluate_and_record()
```

### Main Configurables

| Option | Type | Description |
|--------|------|-------------|
| `--model` / `-m` | str | Model path (overrides config if provided) |
| `--scenario` / `-s` | str | Only `4d_grid` supported |
| `--eta-values` | float (multiple) | Eta values for grid |
| `--process-noise-values` | float (multiple) | Trajectory noise for grid |
| `--kf-process-noise-values` | float (multiple) | EKF process noise for grid |
| `--kf-measurement-noise-values` | float (multiple) | EKF measurement noise for grid |

Fallback defaults for 4D grid:
```python
eta:              [0.0, 0.01, 0.015, 0.02, 0.03]
process_noise:    [0.001, 0.01, 0.1]
kf_proc_noise:    [0.001, 0.01, 0.1]
kf_meas_noise:    [0.001, 0.01, 0.1]
```

### Driving YAMLs

- `configs/online_learning_config.yaml` (standard single run)
- `configs/Used_for_paper/online_learning_config.yaml` (paper config)
- `configs/online_learning_unsupervised_rmspe_config.yaml` (unsupervised RMSPE loss)

### Result Structure

- **Single run**: 
  ```
  {"status": "success",
   "online_learning_results": {
       "dataset_size": int,
       "pretrained_trajectory_results": [TrajectoryResults, ...],
       "online_trajectory_results": [TrajectoryResults, ...],
       "window_count": int
   },
   "drift_detection_dicts": [{window, z_score, glrt, lr_used, ...}, ...]}
  ```
- **4D grid**: 
  ```
  {proc_noise: {kf_proc_noise: {kf_meas_noise: {eta: result_dict}}}}
  ```

### Plots

| Condition | Plot Function | Output |
|-----------|--------------|--------|
| 4D grid complete | `plot_eta_comparison_4d_grid(scenario_results, output_dir)` | Comparison plots across eta for each noise combo |
| Single run (called internally) | `plot_online_learning_results_structured(...)` | Per-trajectory loss/covariance/EKF plots |
| Single run (called internally) | `plot_averaged_online_learning_results(...)` | Averaged across trajectories |

## Shared Internal Flow: `Simulation._run_sweep_iteration`

```
_run_sweep_iteration(overrides, scenario_type, sweep_value, output_subdir, full_mode)
  → apply_overrides(self.config, overrides)
  → update_components_for_sweep(components, config, sweep_param, sweep_value)
  → Simulation(modified_config, updated_components, self.output_dir / output_subdir)
  → Route by config flags:
      full_mode=True         → simulation.run()
      load_model & !train    → simulation.execute_online_learning()
      evaluate_model & !train → simulation.run_evaluation()
      else                   → simulation.run_training()
```

---

## Shared Internal Flow: `OnlineLearning.run_online_learning()`

```
run_online_learning()
  → OnlineLearningTrajectoryGenerator(system_model_params, trajectory_config, eta, M)
  │
  for trajectory_idx in range(dataset_size):
    _run_single_trajectory_online_learning(trajectory_idx)
      │
      for window_idx in range(num_windows):
        │
        ├─ generator.get_next_window(window_size)
        │    → trajectory_physics.sine_accel_step / mult_noise_step / random_walk_step
        │    → samples_model.samples_creation()  [adds measurement noise]
        │
        ├─ _evaluate_and_record(pretrained_model, ...)  [baseline eval]
        │    → _evaluate_window() → _process_single_step() → _forward_and_align()
        │
        ├─ [if drift detected by GLRT z-score]:
        │    _online_training_window(online_model, time_series, ...)
        │      → _initialize_ekf_filters()
        │      → for step in window:
        │          _forward_and_align(require_grad=True)
        │          loss.backward() → optimizer.step()
        │      → adaptive LR via sigmoid(GLRT deviation)
        │
        └─ _evaluate_and_record(online_model, ...)  [post-training eval]
  │
  → plot_online_learning_results_structured()
  → plot_averaged_online_learning_results()
  → return results dict
```

## Critical Analysis: Redundancy & Structure Issues

### Overlap Matrix

| Capability | `run` | `simulate` | `evaluate` | `online_learning` |
|-----------|-------|-----------|-----------|-------------------|
| Single training | ✓ | ✓ | — | — |
| Single evaluation | ✓ | — | ✓ | — |
| Single online learning | ✓ | ✓ | — | ✓ |
| Full pipeline | ✓ | ✓ | — | — |
| Parameter sweep (training) | — | ✓ | — | — |
| Parameter sweep (evaluation) | — | — | ✓ | — |
| Parameter sweep (online learning) | — | ✓ | — | — |
| 4D grid search | — | — | — | ✓ |
| Kalman noise 2D sweep | — | — | ✓ | — |

### Key findings:

1. **`run` is 100% redundant** — every launch.json entry using `run` could use `simulate --mode=training` instead. It provides no unique capability.

2. **`simulate --mode=online_learning --scenario=eta`** is the actual command used for the paper's main experiments — not the `online_learning` command.

3. **The `online_learning` command's only unique value is `4d_grid`** — a specialized sweep pattern. Everything else it does is a subset of `simulate`.

4. **`evaluate` provides convenience** (forced `--model` flag, defaults for sweep values) but is functionally `simulate --mode=training` with eval overrides.

5. **`--scenario` is semantically overloaded:**
   - In `run`: means "which pipeline" (should be `--mode`)
   - In `simulate`: means "which parameter to sweep"
   - In `evaluate`: means "which parameter to sweep"
   - In `online_learning`: means "which grid pattern" (only `4d_grid`)

### In practice (from launch.json):

- **Training** → uses `run` (2×) or `simulate --mode=training` (1×)
- **Evaluation sweeps** → uses `evaluate` (5×)
- **Online learning sweeps** → uses `simulate --mode=online_learning` (4×)
- **4D grid** → uses `online_learning` (1×)
- **Single OL debug** → uses `online_learning` (1×)

### Conclusion:

The CLI grew organically. `simulate` became the de facto universal command, while `run`, `evaluate`, and `online_learning` are legacy convenience wrappers that add confusion without adding capability (except `4d_grid` and `kalman_noise` 2D sweep).
